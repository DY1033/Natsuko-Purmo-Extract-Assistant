01The Problem

同一件事，两种做法。

把解压码塞进压缩包，是最省事的做法，也是最容易失控的做法。区别只在于：密码到底放在谁手里。

过去
  • 解压码直接写在 readme.txt 里
  • 发到群里，截图一转手就外流
  • 想换密码，只能重新打包重发
  • 不知道谁领过、领了几次
  • 链接被爬走，你也没有任何记录
现在
  • 包里只有公钥和一张说明页
  • 解压码留在你自己的服务器上
  • 换公钥即时生效，老包继续能用
  • 每次提取都有记录：时间、IP、结果
  • 停用一条记录，全世界的包一起失效
02Mechanism

三件小事，撑起整个流程。

没有账号体系、没有加密算法科普。它只做三件事，每件都做得足够干脆。

01

公钥与解压码分离

公钥只是一把钥匙孔，可以随便传、随便截图。真正的解压码存在服务端， 只有校验通过才会返回。包里被人翻了个底朝天，也找不到密码。

02

限次与有效期

每条公钥可以单独设最大提取次数和截止时间。用完、过期、手动停用， 三种方式都能让一把钥匙立刻失效，不需要再碰压缩包。

03

24 小时重复查看

同一个 IP 提取过一次，24 小时内再打开不消耗次数 —— 页面关了、网断了、 换台设备想再看一眼，都不用担心次数被吃光。过期后自动重新计数。

03License

拿到授权，四步。

安装版需要一个授权码才能完成安装。授权与域名绑定，一个站点一枚，审核人工处理。

STEP 01

邮箱加密码，不需要企业资质，个人开发者同样可以申请。

STEP 02

提交部署域名

STEP 03

人工确认域名可用后通过，状态和控制台里会实时更新。

STEP 04

在安装向导里填入域名和授权码，激活成功即可完成安装。

04Spec

它其实很小。

一个 Python 进程，一个 SQLite 文件。没有数据库服务，没有消息队列，备份就是复制一个目录。

运行环境 Python 3.8+，或直接 docker run 一个容器
依赖 Flask + SQLite。无 Redis、无 MySQL、无定时任务框架
数据 data/ 目录四个文件，复制即完成备份与迁移
授权校验 每日自动一次，后台可手动刷新；断网 7 天内沿用最近已知状态
提取计数 按公钥 + IP 记录，24h 内重复提取不累加，凭据到期自动清理
页脚署名 Natsuko Program 署名由授权服务器按站点下发，本地不可改
分发方式 GitHub Release 提供源码包，解压后运行 start.sh 或双击 start.bat
05FAQ

你可能会问的。

授权收费吗？
目前免费。审核主要确认两件事：域名真实可用，以及站点确实是用来分发解压码的。 未来如果要收费，会提前在控制台里说明，不会影响已经通过的授权。
换域名了怎么办？
在控制台重新提交一次域名申请，拿到新授权码后重新跑一遍安装向导即可。 data/ 目录原样保留，公钥、解压码、提取记录都不会丢。
服务器连不上授权中心会怎样？
不会立刻停用。客户端会沿用最近一次已知的有效状态，连续 7 天联系不上才会判定失效 —— 机房抖动、临时断网、DNS 抽风都不至于误伤一个正常站点。
授权被驳回或封禁，站点会变成什么样？
整站停用，所有页面跳转到授权状态页，只保留「立即校验」按钮和申请入口。 数据不会删除，恢复授权后立刻回到正常状态。
代码能改吗？能去掉授权吗？
代码是开源的，技术上当然可以。唯一的要求是保留页脚里的版权署名与作者链接 —— 那是这个项目继续维护下去的理由。
